one-click-translator/
├── manifest.json              # 扩展配置文件 (Manifest V3)
├── background.js              # 后台 Service Worker (负责跨域请求代理、多 Key 轮询防限流、API 调用)
│
├── content.js                 # 扩展生命周期总控 (监听快捷键，根据鼠标悬停元素分发“常规文本”或“漫画图片”流水线)
├── content.css                # 页面注入样式 (Shadow DOM 样式隔离，包含“大圆角+自适应宽高的气泡贴纸”样式)
│
├── core/                      # 核心功能模块 (解耦架构)
│   ├── cache.js               # 缓存引擎 (IndexedDB 离线持久化，存取原文与译文映射，拒绝重复请求)
│   ├── manga-sanitizer.js     # 图像清洗与切割 (Canvas 二值化、洗掉敏感背景，抠出白底黑字气泡并记录原图内部相对坐标)
│   ├── overlay.js             # 蒙版渲染引擎 (执行“双框定位法”：使用黄框中心点为绝对锚点，红框尺寸为天花板边界生成贴纸)
│   ├── scanner.js             # 网页正文识别引擎 (提取 DOM 文本与 Range 真实物理坐标)
│   └── translator.js          # 翻译中枢 (纯文本大脑，对接 DeepSeek/Gemini/OpenAI，支持上下文连贯翻译)
│
├── popup/                     # 点击扩展图标弹窗 (快速切换模式)
│   ├── popup.html             # 弹窗面板结构
│   ├── popup.js               # 模式切换与简单设置逻辑
│   └── popup.css              # 弹性卡片布局样式
│
├── options/                   # 独立设置页面 (配置大模型 API Key 轮询池、快捷键等)
│   ├── options.html           # 完整配置页结构
│   ├── options.js             # API Key 存取与轮询池逻辑
│   └── options.css            # 设置页外观样式
│
├── lib/                       # 第三方纯 JS 工具库
│   └── idb-keyval.js          # IndexedDB 极简操作库
│
└── icons/                     # 插件图标

项目	和你整体相似度	最值得借什么	对你来说的问题
ComicTL	90%	漫画检测、OCR、浏览器 Overlay、Local/Cloud 双模式	Cloud 模式仍有 Gemini 路线；需要看其架构是否完全符合你的普通网页分支
Libre Manga Translator	90%+	本地检测/OCR + Gemini + OpenAI-compatible/API + WebGPU，架构非常接近	AGPL；而且它更偏完整漫画翻译器
PanoraTL	80～85%	图片发现、检测、坐标、Overlay、缓存、Gemini 批处理	Gemini 绑定较深；本地 RT-DETR 不一定要照搬
SnapBubble	75～80%	网页图片捕获、视口优先、坐标映射、Overlay	功能面没有你要的完整漫画 pipeline
MikkoParkkola	65～75%	普通网页 DOM 翻译、动态网页、Provider、缓存、页面监听	几乎不解决漫画图片 OCR
Manga-Translator-Extension	75～85%	自定义 Provider、API Key、Model、Base URL、多 LLM	有本地 FastAPI 后端；与你的“纯前端”目标不同
Open-Manga-Translator	75～80%	浏览器图片发现、OCR、Provider 抽象、Bubble rendering	有 Inpainting；你暂时不需要
MangoTL	70～80%	图片翻译 pipeline、浏览器扩展、Provider 配置	依赖本地服务器，AGPL
manga-image-translator	60～70%（整体）	检测/OCR/修复/排版的底层经验	它本身不是你的浏览器插件架构

这些不是 GitHub 官方给出的“相似度”，是我按照你这个 PRD 的模块做的工程结构相似度估算。
例如 ComicTL 当前明确是浏览器扩展，并提供本地 YOLO26 + PaddleOCR + WebLLM，以及 Gemini Cloud 模式；
Libre Manga Translator 则已经支持 WebGPU、Gemini 和 OpenAI/LM Studio API 模式。
